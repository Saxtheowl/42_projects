# Panorama des projets

Ce document presente chaque projet en francais, avec une description claire et accessible.
Chaque projet est decrit en au moins dix lignes pour donner le contexte, les objectifs et les attentes.

## Comment lire ce document
1. Chaque section porte le nom d'un projet tel qu'il apparait dans le depot.
2. Les lignes numerotees resument le but, les livrables et les points de vigilance.
3. Pour des details techniques, reportez-vous aux README et sujets propres a chaque projet.
4. Ce panorama sert d'introduction pour comprendre rapidement l'ensemble du repository.

## Conventions
1. Les noms de projet sont conserves tels quels pour faciliter la navigation.
2. Les descriptions restent generales pour eviter d'inventer des details non confirmes.
3. Les contraintes et livrables precis sont toujours la reference du sujet officiel.

## Glossaire rapide
1. Sujet : le document officiel qui decrit les exigences du projet.
2. Livrable : ce que vous devez remettre (code, script, rapport, binaire).
3. Tests : verifications attendues pour valider le comportement.
4. README : mode d'emploi minimal pour comprendre et executer le projet.
5. Contraintes : regles techniques a respecter (langage, normes, temps, etc.).

## Utilisation du panorama
1. Commencez par identifier les projets prioritaires ou ceux en cours.
2. Pour chaque projet, lisez d'abord le sujet officiel puis revenez ici pour le contexte general.
3. Utilisez ce document comme une carte pour comprendre l'ensemble du depot.
4. Si un projet vous semble flou, cherchez le README ou les docs locales associees.
5. Mettez a jour ce panorama quand un projet evolue ou se termine.

## Structure du depot
1. Les dossiers de projets sont ranges par categorie (ex: systems, web, algo, etc.).
2. Chaque dossier contient le sujet, le code et parfois des scripts d'execution.
3. Certains projets ont des dependances externes (outils, services) a installer.
4. Les scripts a la racine servent souvent a automatiser les verifications.
5. Les README racine et projet donnent les commandes principales.

## Comment verifier un projet
1. Identifiez les commandes de test ou de validation dans le README du projet.
2. Verifiez que les dependances et versions demandees sont installees.
3. Lancez les scripts fournis pour reproduire les cas d'usage standards.
4. Testez aussi des cas limites pour eviter des bugs faciles a manquer.
5. Confirmez que les sorties sont stables et conformes aux attentes du sujet.
